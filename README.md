# Personal Finance Service

Консольное приложение для учёта личных финансов. У каждого пользователя свой кошелёк с категориями, операциями и бюджетами.

## Сборка и запуск

Требуется JDK 26. Приложение использует стандартную библиотеку Java, поэтому отдельная установка библиотек не нужна. Для сборки можно использовать Maven или компилятор `javac` из JDK.

Если Maven установлен, выполните команды из корня проекта.

```sh
mvn package
java -cp target/classes org.example.Main
```

Если Maven не установлен, соберите проект с помощью `javac`. Команды ниже рассчитаны на POSIX-совместимую оболочку.

```sh
mkdir -p target/classes
find src/main/java -name '*.java' > target/sources.txt
javac -encoding UTF-8 -d target/classes @target/sources.txt
java -cp target/classes org.example.Main
```

## Структура проекта

Проект состоит из одного Maven-модуля. Исходники находятся в `src/main/java` и разделены по пакетам.

| Пакет | Ответственность |
| --- | --- |
| [`org.example`](src/main/java/org/example/Main.java) | `Main` задаёт каталог данных и связывает консоль, сервис входа и файловое хранилище. |
| [`org.example.cli`](src/main/java/org/example/cli) | `Console` читает команды, проверяет формат ввода, хранит текущий сеанс и выводит сообщения. Отчёт можно вывести в терминал или записать в файл. |
| [`org.example.core`](src/main/java/org/example/core) | `AuthService` регистрирует пользователей и проверяет учётные данные. `User` владеет своим `Wallet`. Кошелёк хранит категории, бюджеты и историю `Transaction`, рассчитывает итоги и формирует отчёт. `WalletStore` задаёт интерфейс хранения, а `WalletFileFormat` содержит общие операции чтения и записи формата. |
| [`org.example.infrastructure`](src/main/java/org/example/infrastructure) | `FileWalletStore` хранит отдельный файл для каждой учётной записи. При сохранении он пишет во временный файл и затем атомарно заменяет целевой. |

При первом успешном входе пользователя после запуска кошелёк восстанавливается из файла. Во время работы операции и бюджеты хранятся в памяти. Вместе с кошельком сохраняются идентификатор пользователя, логин, соль и хеш пароля.

## Как пользоваться

1. Введите `register`, затем логин и пароль, каждый на отдельной строке.
2. Введите `login` и те же учётные данные.
3. Создайте нужные категории. Затем добавляйте доходы и расходы и устанавливайте бюджеты для категорий расходов.
4. Используйте `report` для просмотра кошелька или `report-file` для экспорта отчёта.
5. Завершите работу командой `exit`. Приложение сохраняет кошельки в папку `.finance-data` в текущем рабочем каталоге. При следующем запуске из того же каталога войдите с прежним логином и паролем.

Команды вводятся без аргументов. Консоль запрашивает данные по одной строке. Названия категорий могут содержать пробелы. Для сумм подходят точка и запятая в качестве десятичного разделителя. Сумма операции должна быть положительной, бюджет может быть нулевым. При превышении бюджета или общих доходов консоль показывает предупреждение с суммой превышения.

## Команды

| Команда | Действие |
| --- | --- |
| `register` | Создать учётную запись. Запрашивает логин и пароль. |
| `login` | Войти. Запрашивает логин и пароль. |
| `logout` | Выйти из учётной записи, чтобы войти под другим пользователем. |
| `income-category` | Создать категорию доходов. Запрашивает название. |
| `expense-category` | Создать категорию расходов. Запрашивает название. |
| `rename-income-category` | Переименовать категорию доходов. Запрашивает текущее и новое названия. |
| `rename-expense-category` | Переименовать категорию расходов. Запрашивает текущее и новое названия. |
| `delete-income-category` | Удалить категорию доходов без операций. Запрашивает название. |
| `delete-expense-category` | Удалить категорию расходов без операций вместе с её бюджетом. Запрашивает название. |
| `income` | Добавить доход. Запрашивает существующую категорию доходов и сумму. |
| `expense` | Добавить расход. Запрашивает существующую категорию расходов и сумму. |
| `budget` | Задать или изменить бюджет. Запрашивает существующую категорию расходов и сумму. |
| `sum-income` | Подсчитать доходы по выбранным категориям или по всему кошельку. |
| `sum-expenses` | Подсчитать расходы по выбранным категориям или по всему кошельку. |
| `report` | Показать итоги, суммы по категориям и остатки бюджетов. |
| `report-file` | Записать тот же отчёт в новый файл UTF-8. Запрашивает путь. |
| `exit` | Сохранить данные и завершить приложение. |

Команды кошелька требуют входа. Для `sum-income` и `sum-expenses` вводите названия категорий по одному на строку. Завершите список пустой строкой. Чтобы получить общую сумму, оставьте пустой первую строку. При неизвестной категории консоль сообщает её название.

При переименовании операции и бюджет остаются в категории с новым названием. Название должно быть уникальным среди категорий того же типа. Удалять можно категории без операций. При удалении категории расходов её бюджет тоже удаляется.

## Как проверить работу

В проекте нет автоматических тестов. После сборки выполните следующий сценарий из корня проекта. Он создаёт отдельный временный каталог, чтобы проверка не затронула ваши кошельки.

```sh
classes="$PWD/target/classes"
check_dir=$(mktemp -d)

(
    cd "$check_dir" || exit 1
    java -cp "$classes" org.example.Main <<'INPUT'
register
demo
demo-password
login
demo
demo-password
income-category
Зарплата
income
Зарплата
100
expense-category
Еда
expense-category
Такси
budget
Еда
30
expense
Еда
35
expense
Такси
10
sum-expenses
Еда
Такси

sum-expenses
Несуществующая категория

report
report-file
report.txt
exit
INPUT

    cat report.txt

    java -cp "$classes" org.example.Main <<'INPUT'
login
demo
demo-password
report
exit
INPUT
)
```

Ожидаемые результаты:

- При расходе на еду появляется предупреждение о превышении бюджета на `5`.
- Сумма расходов по двум категориям равна `45`. Для несуществующей категории выводится сообщение об ошибке.
- Отчёт показывает доход `100.0`, расходы `45.0` и остаток бюджета на еду `-5`.
- Содержимое `report.txt` совпадает с отчётом в терминале. После перезапуска отчёт содержит те же данные.
